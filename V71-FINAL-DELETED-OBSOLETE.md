# Rizo Defense v71 — Deleted / Superseded Systems

Across the rebuild, the active production path no longer relies on:
- the single mutable `wave` value as permanent progression authority;
- direct production QA globals / legacy QA namespaces;
- raw unsigned current-version state/checkpoint trust;
- stored enemy reward/HP/armor or tower spending/cost as authority;
- continuous unstructured wave spawning and direct split-child bursts;
- boss density bypass and 2× extra density allowance;
- simulation-clock target/income/UI control cadence;
- every-frame every-tower full target scans;
- spent-dependent opaque upgrade pricing;
- per-world general starting-cash/reward inflation;
- uncapped Golden stacking;
- simulation/history-dependent placement refund timing;
- `combatStarted` as an economy-permission proxy;
- mutable old runtime URLs with cache-first boot-critical service-worker behavior;
- automatic first-launch install gate;
- scattered overlay toggles as overlay authority;
- implicit/boolean-only Defense phases;
- unconstrained short-phone grid sizing;
- generic landmark rules that flattened world-specific silhouettes;
- 67px dominant road treatment;
- selected-tower debug ring pseudo-element responsibility;
- permanent development ENTRY/GATE labels;
- device-by-device tower sizing;
- event-specific cinematic DOM stacks (Phase 8 uses one reusable host).

## CSS debt reduction inherited from the controlled rebuild
The original active CSS was reduced by roughly 49% during foundation cleanup: 104 media queries → 26 and 3,676 `!important` declarations → 250 inherited non-Defense declarations. Current static audit confirms **zero active Defense `!important` declarations** and no uncontrolled Defense z-index literals.
